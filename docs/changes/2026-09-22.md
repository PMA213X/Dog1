## 1. 网络调试（宿主机系统级配置）

### 1.1 修改原因

原生 Ubuntu 通过网线连接机器狗 YoboGo-10S 时，`eno1` 接口始终 `NO-CARRIER`（物理链路不通）。经排查（换网线、强制降速、充电重启均无效），确认是 HP OMEN 笔记本 Realtek RTL8111/8168 网卡与 UP Board 网口之间的物理层协商兼容性问题。为排除驱动因素并建立可用的网络配置，进行了以下修改。

### 1.2 涉及文件 / 配置

| 对象 | 路径 / 名称 | 修改内容 |
|------|------------|----------|
| 内核驱动包 | `r8168-dkms`（8.055.00-1build1） | 通过 `sudo apt install -y r8168-dkms` 安装，替代内核自带的 r8169 驱动，重启后生效 |
| NetworkManager 连接配置 | `robot`（系统连接配置） | 创建有线连接 `robot`：静态 IP `10.0.0.30/24`、无默认网关、`ipv4.never-default yes`、`route-metric 600` |

### 1.3 涉及模块

- **网络子系统**：NetworkManager（nmcli）、Linux 以太网驱动（r8168 / r8169）
- **关键约束**：`robot` 配置**不能**设置默认网关、**必须** `never-default yes`，否则激活后会抢占 WiFi 默认路由导致断网（当日已踩坑并修复）
- **WiFi + 有线共存策略**：WiFi 负责外网，`robot` 有线配置只处理 `10.0.0.x` 网段，两者不同子网、路由互不冲突

详见 `docs/features/network-debug-notes.md`。

## 2. Webots 仿真环境搭建

### 2.1 修改原因

需要在无实机的情况下验证四足步态控制算法。选定方案：Webots + C++ 控制器（与教材 Mini Cheetah 架构一致，不依赖 ROS）。

### 2.2 涉及文件 / 配置

| 对象 | 路径 / 名称 | 修改内容 |
|------|------------|----------|
| Webots 软件包 | `/usr/local/webots/` | 通过 Cyberbotics apt 源安装 `webots` 2025a（R2025a） |
| 中文界面配置 | `~/.config/Cyberbotics/Webots-R2025a.conf` | `[%General]` 段设置 `language=zh_CN`，界面切换为简体中文 |
| 仿真项目 | `webots-sim/` | 新建/完善 Webots 项目：世界文件 + C++ 控制器 + URDF 资源 |
| 世界文件 | `webots-sim/worlds/mini_cheetah.wbt` | `#VRML_SIM R2025a`，使用 Webots 内置节点构建（不依赖外部 PROTO），`basicTimeStep 4`（250Hz 控制周期） |
| 控制器 | `webots-sim/controllers/mini_cheetah_controller/mini_cheetah_controller.cpp` | 334 行 C++：PD 站立 + trot 对角小跑步态 + IMU 读取 + 键盘模式切换 |
| 控制器 Makefile | `webots-sim/controllers/mini_cheetah_controller/Makefile` | 基于 Webots 标准 `Makefile.include`（`USE_C_API = true`），已编译成功（`build/release/` 下产出可执行文件） |

### 2.3 涉及模块

- **仿真控制**：站立模式（关节 PD，KP=[3,3,3]、KD=[1,0.2,0.2]、力矩限幅 15N·m）；trot 模式（周期 0.5s、支撑相 0.25s、抬腿高 0.04m、FR+HL / FL+HR 对角相位）
- **按键**：`S` 站立 / `T` trot / `R` 复位到站立

详见 `docs/features/webots-sim-guide.md`。
