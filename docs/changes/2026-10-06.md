## P2 训练改进与停止旧训练

- 日期：2026-10-06
- 原因：依据 `/root/audit_p1_regression_cause` 复盘，P2 在 320k～1060k
  的 Gate 几乎全失败：forward 约 `0`（要求 `>=0.18`）、计划位移残差约
  `5.04 m`（要求 `<=0.35 m`）、真实四足接触约 `0.42`（要求 `>=0.85`）。
  根因按优先级为均匀命令覆盖不足、10k 分段重复 seed 且只完成一次 PPO
  update、移动奖励弱于站立、以及 raw displacement/planned residual 命名
  混用。

### 修复实现

1. P2 命令改为 16 槽覆盖循环：
   - Gate forward `8/16=50%`，`vx∈[0.18,0.25]`、`vy=0`、`wz=0`；
   - zero `4/16=25%`；
   - 左右横移和左右偏航各 `1/16`；
   - 每 5 s 重采样语义不变，P1 和 P3～P7 的命令语义不变。
2. 正式训练 seed 改为
   `BASE_TRAINING_SEED + 阶段索引×1,000,000 + 本地 phase-step offset`，
   每个 10k/50k 分段不再复用相同命令随机序列。
3. 新增阶段调度函数：
   - P2 分段与正式 Gate 间隔为 `50,000`，至少容纳多个
     `2048×4=8192` 完整 PPO rollout；
   - P0/P1/P4 及其他阶段仍为 `10,000`，P4 DR 逐级语义和所有阶段总预算
     不变。
4. P2 奖励重新平衡：
   - `distance=0.50`；
   - `true_four_foot_contact=0.8`；
   - `support_gap=-0.15`；
   - `gait=-0.05`，部分接触不再得到正 gait 奖励；
   - 新增 `command_speed_progress`、`command_displacement_progress`，
     权重各 `1.5`，分别按平面速度和单周期机体系位移相对命令归一；
   - P1 与 P3～P7 不启用新增项，原权重语义保持。
5. 评估遥测拆分：
   - 同时输出 `raw_displacement_m`、`planned_displacement_m`、
     `planned_residual_m`、`drift_component`；
   - stop 的 `drift_m` 明确为原始位移，移动命令的 `drift_m` 明确为
     计划位移残差；
   - mode 报告增加 `case_values`，stop/forward 分 case 输出位移、速度、
     命令误差和真实四足接触。
6. PPO loss/entropy 不重复实现：SB3 原生记录 `train/loss`、
   `train/policy_gradient_loss`、`train/value_loss`、
   `train/entropy_loss`、`train/approx_kl`、`train/clip_fraction`。

### 续修复：Gate 端口有界等待与 forward 单变量修复

- 日期：2026-10-06
- 只读诊断：新配置在 `1180k～1230k` 的 contact 曾达到 `0.9227`，
  `1280k` 回退到 `0.8046`；forward 始终约 `-0.0013`（目标
  `>=0.18`），planned residual 约 `4.90 m`。实际终止原因为
  `run_stages` 启动 Gate 时端口 `1234` 仍被占用，属于旧
  Webots/controller 退出竞争，不是 OOM 或指标逻辑错误。

#### 端口安全重试

- `run_gate()` 改用 `wait_for_gate_ports_free()`：Gate 启动前对
  `1234/11452-11455` 每 `0.25 s` 复查一次，最长等待 `60 s`；
- 只有真实 `LISTEN` 进入重试，`TIME-WAIT`、`CLOSE-WAIT` 等非监听残留
  继续放行；
- 等待期间只等旧 Webots/controller 自然退出，不执行破坏性 kill；
- 超时错误包含 timeout、attempts、last error、实际 listening 与
  active residue 端口，以及不启动 `rl.evaluate`、不 kill 的诊断；
- 测试覆盖“占用一次→释放→成功启动 Gate 子进程”和“持续 LISTEN→超时、
  只执行诊断 `ss`、未启动 Gate 子进程”。

#### forward 单变量修复

- 历史探针：`ACTION_TARGET_RATE_LIMIT=0.01 rad/s` 时 `360/360 finite`、
  contact 比例 `1.0`，但 10 s episode 每关节最多只允许变化
  `0.10 rad`，无法解释持续 forward≈0；`0.75 rad/s` 探针 contact 均值
  仅 `0.333`，已出现接触丢失。
- 因此只将 `ACTION_TARGET_RATE_LIMIT` 从 `0.01` 调整为候选下界
  `0.03 rad/s`：每周期上限 `0.0006 rad`、10 s 最多 `0.30 rad`，
  仍比 `0.75` 低 25 倍。
- 本轮未改 reward 权重，保留既有 P2
  `command_speed_progress=1.5`、`command_displacement_progress=1.5`、
  `distance=0.50`、`true_four_foot_contact=0.8`、
  `support_gap=-0.15`、`gait=-0.05`。
- 未改 PPO 超参、P1/P2 contact Gate 阈值 `0.85`、总预算 `1,500,000`、
  P2 `50,000` 分段、16 槽命令、seed 去重或 drift/case telemetry。
- 隔离 contact 目标仍按 `>=0.95` 监测；当前没有 `0.03 rad/s` 的真实
  Webots 隔离探针，这是本轮需要训练/早期 Gate 继续验证的遗留风险。
