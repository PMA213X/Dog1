- 日期：2026-10-06

### 修复实现

1. P2 命令改为 16 槽覆盖循环：
   - Gate forward `8/16=50%`，`vx∈[0.18,0.25]`、`vy=0`、`wz=0`；
   - zero `4/16=25%`；
   - 左右横移和左右偏航各 `1/16`；
   - 每 5 s 重采样语义不变，P1 和 P3～P7 的命令语义不变。
2. 正式训练 seed 改为
   `BASE_TRAINING_SEED + 阶段索引×1,000,000 + 本地 phase-step offset`，
   每个 10k/50k 分段不再复用相同命令随机序列。
3. 新增阶段调度函数：
   - P2 分段与正式 Gate 间隔为 `50,000`，至少容纳多个
     `2048×4=8192` 完整 PPO rollout；
   - P0/P1/P4 及其他阶段仍为 `10,000`，P4 DR 逐级语义和所有阶段总预算
     不变。
4. P2 奖励重新平衡：
   - `distance=0.50`；
   - `true_four_foot_contact=0.8`；
   - `support_gap=-0.15`；
   - `gait=-0.05`，部分接触不再得到正 gait 奖励；
   - 新增 `command_speed_progress`、`command_displacement_progress`，
     权重各 `1.5`，分别按平面速度和单周期机体系位移相对命令归一；
   - P1 与 P3～P7 不启用新增项，原权重语义保持。
5. 评估遥测拆分：
   - 同时输出 `raw_displacement_m`、`planned_displacement_m`、
     `planned_residual_m`、`drift_component`；
   - stop 的 `drift_m` 明确为原始位移，移动命令的 `drift_m` 明确为
     计划位移残差；
   - mode 报告增加 `case_values`，stop/forward 分 case 输出位移、速度、
     命令误差和真实四足接触。
6. PPO loss/entropy 不重复实现：SB3 原生记录 `train/loss`、
   `train/policy_gradient_loss`、`train/value_loss`、
   `train/entropy_loss`、`train/approx_kl`、`train/clip_fraction`。

## Rapid Play 首次人工测试闪退复盘与日志修复

- 日期：2026-10-06
- 原因：用户反馈键盘/手柄有反应但数秒后窗口快速关闭，且两个历史
  `rapid_play_*.jsonl` 为 0 字节。

### 诊断证据

- 历史 `webots_0.log` 中两次 play 均有
  `RL_CONTROLLER_PLAY_INPUT_READY`、连接、reset 和首个 control
  diagnostic，没有 `Traceback`、`RL_CONTROLLER_ERROR`；
- `webots_eval_world.log` 只有 controller 正常断开等待，无 Webots
  崩溃或端口异常；
- 历史 JSONL 为空的直接原因是 `rl.play.main()` 创建了
  `JsonlPlayLogger`，但调用 `run_play_session()` 时漏传 `logger=logger`；
  `run_play_session` 中的 logger 分支从未执行；
- 修复后真实 Webots `--max-steps 1000` 复现退出码 `0`，耗时约
  `13.643 s`，生成 1,000 行 JSONL，所有动作、观测和 latent 字段有限；
- 注入前 100 帧 `vx=0.6` 的真实 Webots 冒烟完成 200 步，退出码 `0`，
  100 帧 `reason=policy`、100 帧 `reason=input_timeout`，无 NaN/Inf。

### 结论与修复

1. 可证实的代码缺陷是 JSONL 日志参数漏传，已补上
   `logger=logger`，并新增入口回归测试防止再次漏传；
2. 用户看到的“闪退”与当前可复现行为一致：play 使用 fast 模式，
   `--max-steps 1000` 在约 14 秒内正常完成后主动关闭 Webots，不是
   Python 异常、controller 退出、TCP 断开、非有限动作或急停误触发；
3. 用户原始终端退出码未被日志系统保存，因此不把历史运行武断标为
   `0`；当前修复后的 10/200/1000 步真实复现均为 `0`；
4. 持续人工测试应改为 `--max-steps 0`；有限测试结束必须检查
   `PLAY_SESSION_DONE` 和 JSONL 行数。

## Rapid 稳定训练 P0：有效支撑、逐足滑移与全程 low-speed 命令

- 日期：2026-10-07（补记于 2026-10-06 变更记录）
- 原因：final Gate 暴露 stop 四足比例仅 `0.00882`、forward 平均接触足仅
  `2.39056`、足滑 `0.05394 m/s`、`height_p05=0.23623 m`；原 moving 分支又
  按任意接触足数直接给 `0.5*n` 正分，可能以低姿拖行或非 toe 蹭地换奖励。
  同时原 `foot_slip=-20` 且从 `0.02 m/s` 才起罚，对 2.7 倍越界的负反馈不足。
- 范围：只修改 Rapid reward/命令课程相关实现与对应测试、功能文档；不修改
  `tools/gen`、`controllers/rl_agent`、world、Gate 阈值、checkpoint 或其他代理
  文件，不启动训练，不执行 Git 操作。

### 最小实现

1. `rl/reward.py`：
   - 接触奖励只统计有效 toe：精确 toe 接触之外，还要求
     `height>=0.25 m` 且 `|roll|/|pitch|<=0.25 rad`；当前没有逐 toe 法向力，
     用与 Gate `height_p05`、姿态 p95 对齐的高度/姿态组合作为等效支撑判据；
   - 移动分支删除按任意接触足数的 `0.5*n` 正奖励；`n>=2` 该分项为 `0`，
     `n<2` 保留缺失足重罚，`n<2.5` 保留连续 `-2/足` 缺口；
   - `foot_slip` 对四个有效 toe 各取 3 维接触点速度水平模长后取均值，
     测试明确不同足速度不会被最后一足覆盖；
   - Rapid 起罚线收紧为 `0.015 m/s`、权重改为 `-40`；
   - shank、机身等所有非 toe 接触继续由 `non_foot_contact` 汇总，权重提升为
     `-60` 大额惩罚；未放宽摔倒终止、动作裁剪、相邻动作限速、目标限速、
     力矩约束或急停。
2. `rl/rapid_finetune_vec_env.py`：
   - 全程只按 75% `vx=0.10–0.18`、25% zero 采样；
   - 删除 `100k` 后 `vx=0.18–0.25`、`vy=±0.10`、`wz=±0.30` 分支；
   - actor 仍为 `0–100k` critic-only、`100k` 解冻，命令仍每 1000 步 Gate
     episode 保持，同步 reset 后才重采样。
3. actor/critic 与 PPO 不改：`RAPID_STAGE_ACTOR_START=100_000`、
   `target_kl=0.01`，adaptation 条件解冻逻辑保持。
