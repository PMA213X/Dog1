## 1. 硬件连接步骤

### 1.1 准备工作

| 项目 | 说明 |
|------|------|
| 机器人型号 | YoboGo（山东优宝特智能机器人） |
| 主控板 | UP Board (Atom X5-Z8350, 4GB RAM) |
| 操作系统 | Ubuntu Linux |
| 机器人 IP | `10.0.0.34` |
| 通信协议 | LCM（进程间）、SPI（UP Board↔SPIne板）、CAN（SPIne板↔电机） |

### 1.2 连接顺序

```
步骤 1: 准备网线
    ├── 确认网线可用（推荐 Cat5e 或 Cat6）
    └── 确认网线两端接口完好

步骤 2: 连接网线
    ├── 一端 → 机器人以太网口
    └── 另一端 → 电脑以太网口（或通过交换机/路由器）

步骤 3: 开机
    ├── 先打开机器人电源开关
    ├── 等待 30-60 秒让系统启动
    └── 启动完成后再进行网络配置

步骤 4: 电脑端配置
    ├── 关闭 WiFi
    ├── 配置有线网络 IP
    └── 运行 connect_check.sh 验证连接
```

### 1.3 注意事项

- ⚠️ **必须使用有线以太网连接**，不能通过 WiFi 连接机器人
- ⚠️ **开机顺序**：先开机器人，再配置电脑网络
- ⚠️ **关机顺序**：先关闭机器人上的软件，再断开网线

## 2. 电脑网络配置

### 2.1 关闭 WiFi

**方法一：命令行（推荐）**

```bash
# 关闭 WiFi
nmcli radio wifi off

# 确认 WiFi 已关闭
nmcli radio wifi
# 应输出: disabled
```

**方法二：图形界面**

```
点击系统托盘 → WiFi 开关 → 关闭
```

### 2.2 配置有线网络 IP

**方法一：nmcli 命令（推荐）**

```bash
# 查看有线网络连接名称
nmcli connection show

# 设置静态 IP（假设接口名为 eth0）
# 注意: x 为 2-33 或 35-254 之间的数字，不能与机器人 IP 冲突
sudo nmcli connection modify "有线连接1" \
    ipv4.method manual \
    ipv4.addresses "10.0.0.x/24" \
    ipv4.gateway "10.0.0.1" \
    ipv4.dns "10.0.0.1"

# 重新激活连接
sudo nmcli connection up "有线连接1"
```

**方法二：临时设置（重启后失效）**

```bash
# 查看当前接口名称
ip link show

# 假设接口名为 enp3s0
sudo ip addr add 10.0.0.x/24 dev enp3s0
sudo ip link set enp3s0 up
```

**方法三：Ubuntu 图形界面**

```
系统设置 → 网络 → 有线 → 选项/齿轮图标 → IPv4 设置
├── 方法: 手动
├── 地址: 10.0.0.x
├── 子网掩码: 255.255.255.0
├── 网关: 10.0.0.1
└── DNS: 10.0.0.1
```

### 2.3 虚拟机网络配置（如使用虚拟机）

```
虚拟机设置 → 网络适配器 → 桥接模式（Bridged）
├── 桥接至: 有线网卡（不是 WiFi 网卡！）
└── 确认虚拟机内也配置了 10.0.0.x 的 IP
```

### 2.4 IP 地址规划

| 设备 | IP 地址 | 说明 |
|------|---------|------|
| 机器人 | `10.0.0.34` | 固定 |
| 网关 | `10.0.0.1` | 路由器（如有） |
| 你的电脑 | `10.0.0.x` | x = 2~33 或 35~254 |
| 广播地址 | `10.0.0.255` | 自动计算 |

## 3. 脚本工具使用说明

所有脚本位于 `scripts/` 目录下。

### 3.1 连通性检查 — `connect_check.sh`

**功能**: 检查本机与机器人之间的网络连通状态

**使用**:
```bash
bash scripts/connect_check.sh
```

**检查项**:
- 本机网络配置（IP、子网掩码、默认网关）
- WiFi 是否关闭
- 是否在 10.0.0.x 子网内
- Ping 机器人（5 次）
- SSH 自动登录测试（需要 sshpass）

**输出示例**:
```
========== 检查必要依赖 ==========
[  OK] sshpass 已安装 — 可自动测试 SSH 连接
[  OK] 必要依赖检查通过

========== 1. 本机网络配置 ==========
[  OK] 主要网络接口: enp3s0
[INFO] 本机 IP 地址: 10.0.0.100
[INFO] 默认网关: 10.0.0.1

========== 2. 本机 IP 是否在 10.0.0.x 子网内 ==========
[  OK] 本机 IP (10.0.0.100) 在 10.0.0.0/24 子网内

========== 4. Ping 机器人 ==========
[  OK] 机器人 10.0.0.34 可达
```

### 3.2 探测机器人内部资源 — `explore_robot.sh`

**功能**: SSH 连接到机器人，全面探测系统信息、软件目录、硬件设备

**使用**:
```bash
bash scripts/explore_robot.sh
```

**探测内容**:
| 类别 | 探测项 |
|------|--------|
| 系统信息 | `uname -a`、`/etc/os-release` |
| 硬件资源 | 磁盘、内存、CPU 和进程概览 |
| 用户目录 | `/home/user/`、`/home/dog/` |
| 软件目录 | `robot-software/`、`track1.1/`、`dogvision/` |
| 硬件设备 | `/dev/video*`、`/dev/spidev*` |
| 网络进程 | 网络接口、关键进程、运行的服务 |

**输出**: 结果保存到 `scripts/robot_explore_result.txt`

### 3.3 实时状态监控 — `robot_status.sh`

**功能**: SSH 到机器人获取实时运行状态

**使用**:
```bash
# 单次查看
bash scripts/robot_status.sh

# 持续监控（每 5 秒刷新）
bash scripts/robot_status.sh --loop
```

**监控内容**:
- 机器人在线状态
- CPU 温度和使用率
- 内存使用情况
- 磁盘空间
- 网络接口状态和流量
- 关键进程（mit_ctrl, track, dogvision）
- 硬件设备（SPI、hwmon）

### 3.4 文件传输 — `scp_to_robot.sh`

**功能**: 将本地文件或目录传输到机器人

**使用**:
```bash
# 传输文件（默认到 /home/user/）
bash scripts/scp_to_robot.sh /path/to/file.txt

# 传输文件到指定目录
bash scripts/scp_to_robot.sh /path/to/file.txt /home/user/robot-software/

# 传输整个目录（自动递归）
bash scripts/scp_to_robot.sh /path/to/my_project/ /home/user/
```

**参数说明**:
| 参数 | 必填 | 说明 |
|------|------|------|
| `<本地路径>` | 是 | 要传输的文件或目录路径 |
| `[远程目录]` | 否 | 机器人上的目标目录（默认 `/home/user/`） |

### 3.5 脚本依赖

| 依赖 | 用途 | 安装命令 |
|------|------|----------|
| `sshpass` | 自动 SSH 登录 | `sudo apt install sshpass` |
| `ping` | 网络连通性测试 | `sudo apt install iputils-ping` |
| `ip` | 网络配置查看 | `sudo apt install iproute2` |
| `nmcli` | 网络管理 | `sudo apt install network-manager` |

**一键安装所有依赖**:
```bash
sudo apt install sshpass iputils-ping iproute2 network-manager
```

## 4. 常见问题排查

### 4.1 Ping 不通机器人

```
症状: ping 10.0.0.34 显示 "Destination Host Unreachable" 或 "Request timeout"
```

**排查步骤**:

```
1. 检查网线连接
   └── 确认网线两端都插好，指示灯亮起

2. 检查机器人是否开机
   └── 观察机器人的电源指示灯

3. 检查本机 IP 配置
   $ ip addr show
   └── 确认有线接口有 10.0.0.x 的 IP

4. 检查是否在同一子网
   └── 本机 IP 必须是 10.0.0.x（x ≠ 34, x ≠ 1）

5. 检查 ARP 表
   $ arp -a | grep 10.0.0
   └── 能看到机器人的 MAC 地址

6. 检查防火墙
   $ sudo ufw status
   └── 如有防火墙，暂时关闭测试: sudo ufw disable
```

### 4.2 SSH 连接被拒绝

```
症状: ssh user@10.0.0.34 显示 "Connection refused"
```

**排查步骤**:

```
1. Ping 测试
   $ ping 10.0.0.34
   └── 确认网络层连通

2. 检查 SSH 端口
   $ nmap -p 22 10.0.0.34
   └── 确认 22 端口开放

3. SSH 端口扫描
   $ nc -zv 10.0.0.34 22
   └── 测试 TCP 22 端口

4. 可能的解决方法
   └── 机器人上重启 SSH: sudo systemctl restart ssh
```

### 4.3 SSH 密码错误

```
症状: 输入密码后显示 "Permission denied, please try again"
```

**排查步骤**:

```
1. 确认用户名
   └── 用户名: user（注意不是 dog）

2. 确认密码
   └── 密码: 123456（区分大小写）

3. 手动测试
   $ ssh user@10.0.0.34
   └── 手动输入密码确认

4. 检查是否被锁定
   └── 连续失败多次可能触发账户锁定
```

### 4.4 WiFi 无法关闭

```
症状: nmcli radio wifi off 不生效
```

**排查步骤**:

```
1. 检查 NetworkManager 状态
   $ systemctl status NetworkManager

2. 重启 NetworkManager
   $ sudo systemctl restart NetworkManager

3. 硬件开关
   └── 检查笔记本上的 WiFi 物理开关或 Fn+功能键

4. 临时禁用
   $ sudo ip link set wlan0 down
```

### 4.5 虚拟机无法连接

```
症状: 虚拟机内 ping 不通，但宿主机可以
```

**排查步骤**:

```
1. 确认网络模式
   └── 虚拟机必须设置为 "桥接模式"（不是 NAT！）

2. 桥接网卡选择
   └── 桥接到有线网卡，不是 WiFi 网卡

3. 虚拟机内配置 IP
   └── 虚拟机内也要配置 10.0.0.x 的 IP

4. 防火墙
   $ sudo ufw status
   └── 关闭虚拟机防火墙
```

### 4.6 SSH 连接慢

```
症状: SSH 连接需要等很长时间才响应
```

**解决方法**:

```bash
# 禁用 DNS 反向解析
ssh -o UserKnownHostsFile=/dev/null -o StrictHostKeyChecking=no user@10.0.0.34

# 或在 ~/.ssh/config 中添加
Host 10.0.0.34
    User user
    StrictHostKeyChecking no
    UserKnownHostsFile /dev/null
    GSSAPIAuthentication no
```

## 5. 远程操作注意事项

### 5.1 安全注意事项

- ⚠️ **不要在公网暴露机器人** — 机器人只应在局域网中使用
- ⚠️ **定期修改密码** — 默认密码 `123456` 仅用于开发阶段
- ⚠️ **操作前备份** — 远程修改文件前先备份到本地
- ⚠️ **谨慎使用 sudo** — 远程操作时 sudo 权限需特别小心

### 5.2 操作规范

```
操作前:
  ├── 确认网络连接正常（运行 connect_check.sh）
  ├── 备份要修改的文件
  └── 了解要执行的命令的含义

操作中:
  ├── 使用 screen 或 tmux 进行长时间运行的任务
  ├── 分步执行，不要一次性运行多个高风险命令
  └── 保存重要日志和输出

操作后:
  ├── 验证修改结果
  ├── 检查关键进程是否正常
  └── 确认机器人功能正常
```

### 5.3 常用远程操作

```bash
# SSH 登录
ssh user@10.0.0.34

# 使用 screen 保持会话
screen -S robot      # 创建新会话
screen -r robot      # 恢复会话
Ctrl+A, D            # 分离会话
Ctrl+A, K            # 终止会话

# 后台运行程序
nohup ./mit_ctrl &

# 查看日志
tail -f /path/to/log/file
```

### 5.4 紧急恢复

如果机器人出现异常：

```
1. 尝试 SSH 连接
   $ ssh user@10.0.0.34

2. 如果 SSH 无法连接
   └── 通过物理方式重启机器人

3. 如果系统无法启动
   └── 检查 /home/user/ 下的日志文件
   └── 考虑重新刷写系统镜像
```
